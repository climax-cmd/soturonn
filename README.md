# 東日本大震災の被災経験と地震保険の加入：家計パネルデータによる分析

卒業論文（実証ミクロ経済学）の分析コードです。R Markdown で、個票データの前処理から推定・頑健性の確認までを行います。

> **データは含みません。** 分析に使う個票データは利用申請が必要なため、このリポジトリにはコードだけを置いています。推定結果も載せていません。

## 研究の概要

**問い**

1. 東日本大震災で住居や家財に被害を受けた世帯は、その後、地震保険に加入するようになったか（主分析）
2. 震災前に加入していた世帯は、その後も加入を続けたか。被害や、地震保険への不満とどう関連するか

**データ**

- 日本家計パネル調査（KHPS、慶應義塾大学パネルデータ設計・解析センター）2007〜2018年調査
- 東日本大震災に関する特別調査（GEES、KHPS版）第1回（2011年6月）・第2回（2011年10月）

同じ世帯を震災の前から後まで追跡できるため、震災前の加入状況や推移と合わせて、被害の有無による違いを比べられる点がこの分析の特徴です。

## 分析の方法

| | 内容 |
|---|---|
| 主分析 | イベントスタディ型の差の差分析（DID）。被害あり・なしの世帯を、震災前（基準年は2011年1月の調査）からの加入率の変化で比べる |
| 推定式 | 線形確率モデル。世帯固定効果＋調査年固定効果、標準誤差は世帯でクラスタリング（`fixest::feols`） |
| 識別の確認 | 震災前の係数がすべて0かの検定、震災前の傾きの差の推定（平行トレンドの確認） |
| 頑健性 | 地域×年固定効果、震災前の所得三分位×年固定効果、基準期間の変更、目的変数の定義の変更、分析期間の延長（熊本地震を考慮した九州除外版を含む）など |
| 傾向スコアマッチング | 震災前の属性によるロジットの傾向スコアで、同じ地域の中から 1:2 の最近傍マッチング（`MatchIt`）。マッチング後のバランスの確認と、震災前の期間に当てはめたプラセボ |
| 加入の継続 | 震災前に加入していた世帯について、「震災前の窓」と「震災後の窓」で継続率の差を比べる差の差。不満の有無・被害の有無で比較 |

分析の設計で意識した点：

- **推定の指定は結果を見る前に決め**、主分析と頑健性の結果はすべて報告する。結果を見た後に追加した確認は、その旨を明記して区別している
- 震災後の所得や資産は被害の影響を受けうるため（bad control）、統制変数には入れず、異質性は震災前の値で分ける
- 標本が小さいため、係数は95%信頼区間で示し、有意でない結果は「効果がない」ではなく「この標本では検出できなかった」と解釈する

## コードの構成

| 順 | ファイル | 内容 |
|---|---|---|
| 1 | `khps_preprocess.Rmd` | 年ごとに列番号の異なる CSV を変数対応表で読み込み、公式集計表（GT）との照合、ID の付け替え、パネルの整合性チェック、GEES の接続を行う |
| 2 | `analysis_data.Rmd` | 主分析の分析用データ（イベントスタディ用のパネル、傾向スコアの推定）を作る |
| 3 | `estimate_rq1.Rmd` | 主分析・頑健性・傾向スコアマッチングの推定 |
| 4 | `rq3_data.Rmd` | 加入の継続の分析用データ（震災前・震災後の窓）を作る |
| 5 | `estimate_rq3.Rmd` | 加入の継続の推定 |
| - | `share_utils.R` | 個票データを守るための共通関数（下記） |

入力・出力のパスは、各 Rmd の `params` で指定します。

## 個票データの取り扱い

データの利用規約を守るため、次の仕組みを入れています（`share_utils.R`）。

- **出力先の制限**：前処理済みデータやレポートが、共有フォルダの中に書き出されないように確認する（`sh_check_dir`）
- **共有用モード**：`params$share_mode = TRUE` で Knit すると、件数が閾値（既定は10）未満のセルを伏せる。合計からの引き算で少数のセルが戻せる場合も伏せる（`sh_n`、`sh_n_compl`、`sh_mask_counts`）
- 共有用モードでは、ID の照合、範囲チェック、個別の値が出る表を出力しない（`sh_private`）

## 実行環境

- R（RStudio Server、Docker）
- パッケージ：`dplyr`、`tidyr`、`readr`、`purrr`、`stringr`、`ggplot2`、`knitr`、`fixest`、`MatchIt`
- PDF の出力には XeLaTeX（`bxjsarticle`）

実行には、データ提供元から個票データと配布資料（調査票・コードブックなど）を入手し、そこから変数対応表（`khps_var_map.csv` など）を作る必要があります。

## 生成AIの利用について

コードの作成には生成AI（Claude）を利用しました。研究課題と分析の設計、推定の指定の決定、結果の検証は自分で行っています。個票データ・前処理済みデータ・推定結果は、AIに読み込ませていません。コードは、公開されている調査票やコードブックをもとに作成しました。
